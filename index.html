How a Command Reaches the Device

The generator listens for a short text command over the network. Unity, Unreal, the control app, and the C++/Java samples in the manual all send the same format.

01

Something happens in the scene

An event in the VR or AR experience — entering a room, a fire breaking out — decides it's time for a scent.

02

A command goes out

A UDP message names the port, the intensity, and how long the fan should run for.

03

The cartridge sprays

The matched cartridge releases into the airflow, and the fan clears whatever scent was there before.

04

It reaches the room

Across the generator's 30 m² coverage, the scent lands in sync with the sound and visuals.

OUT,[port 01–10],[intensity 0100–0500],1,[fan time 1000–9000 ms],1000

The two fixed fields in the middle and at the end are internal — the manual notes they shouldn't be changed. The port number is a physical slot (1–10) — whatever scent you've loaded into it above is what fires.

Triggering It From Node.js

The manual only shows C++ and Java samples. This repo has the same UDP message in JavaScript as a real, tested tool — not just a snippet — using Node's built-in dgram module. It runs as a standalone script, not inside a browser — browsers can't open raw UDP sockets, which is also why the ports above only simulate the command rather than firing it.

// tools/protocol.js — the wire format from user guide section 3.2 function encodeCommand({ port, intensity = 100, fanMs = 2000 }) { return [ 'OUT', String(port).padStart(2, '0'), String(intensity).padStart(4, '0'), '1', String(fanMs).padStart(5, '0'), '1000' ].join(','); } // tools/activate-scent.js — sends it for real const socket = dgram.createSocket('udp4'); socket.send(encodeCommand({ port: 2, intensity: 150, fanMs: 3000 }), DEVICE_PORT, DEVICE_IP);

Fire one port: node tools/activate-scent.js 2 --intensity 150 --fan-ms 3000

The CLI's built-in --scenario flag still knows the original 10 tactical ports (see tools/scenario-catalog.js) — the library/scent picker above is a page-only planning view for the fuller catalog and doesn't change what's wired to the CLI or bridge, which always just means "fire physical port N."

The user guide PDF doesn't print the UDP port, but Olorama's separate C++ integration guide does: 5010 by default, which is what these tools use. If your unit differs, override it with --host/--port or the OLORAMA_HOST/OLORAMA_PORT env vars.

No physical generator on hand? npm run simulate starts tools/scent-device-simulator.js, a local UDP listener that decodes the same command and prints which cartridge and intensity it received. npm test runs the automated suite against it.
